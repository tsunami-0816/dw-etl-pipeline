# 简历项目描述 · dw-etl-pipeline

> 口径日期：2026-11-24｜所有数字来自实测产物，出处见文末映射表；未验证/未达成项已单列。

## A 一句话

SaaS 经营分析四层数仓：MySQL 存储过程 + Spark/pandas 重算对账，21 表、12 项指标。

## S 背景

SaaS 运营每天要看 GMV、新增、退款率、ROI，原先是人工拉数。项目在 16GB 内存、RTX 2050 4G 的单机约束下，用固定种子造数复现 90 天经营链路，不引入 Hadoop/Flink/Airflow。

## T 目标（只写最终实测）

1. 四层链路单日跑通且同日重跑不翻倍 —— **达成**（`run_daily` 退出 0，重跑 `skipped`）。
2. 90 天 DWS 由 Spark 重算，与存储过程逐日对账 0 差异 —— **达成**（`diff=0`）。
3. 慢查询优化后提升 ≥3 倍 —— **未达成**（0.79× / 1.05× / 0.79×，当前基线仅 1.7 万行）。

## A 动作

- ODS→DWD→DWS→ADS 用 5 个存储过程封装，按日删写 + 唯一键 upsert + `GET_LOCK`，解决重跑翻倍。
- DWD/DWS 用 `RANGE COLUMNS(dt)` 月分区、唯一键含分区列；用户画像用 SCD2 管有效期。
- DQ01–DQ05 双实现：SQL 内联 + Python 复跑，逐字段对齐，P0 阻断下游、P1 告警。
- Spark 3.5 重算 90 天 DWS，pandas 同口径兜底，逐日 full outer join 对账，差异退出 4。
- `run_daily` 固定 0/2/3/4/5 退出码，`run_summary.json` 作机器断言入口；四层 pytest 共 53 条。

## R 结果（全部实测）

- 规模：21 张表、5 个存储过程、12 项指标、5 条 DQ 规则。
- 测试：53 passed（L1 49 / L2 3 / L3 1 / L4 1），验收 20/20，open P0/P1=0。
- 单日：ODS 2601 / DWD 884 / DWS 31 / ADS 55，GMV 397131.3200，两次一致；对账 diff=0。
- 压测：并发 10/20/50 时 p95 4.66 / 10.26 / 30.6ms，TPS 3231 / 3059 / 2677，错误率 0。
- 未验证：生产规模数据、Allure HTML（本机未装 CLI）、Hadoop/Flink 集群。

## D 可演示点（均来自验收清单）

1. `run_daily.py --date 2026-11-28` 退出 0，`run_summary.json` 各层行数与 GMV 可核对（B-01）。
2. 同日再跑返回 `status=skipped`，各层行数不翻倍（B-01 幂等断言）。
3. 注入 100% 空渠道 → `exit 2` blocked、DWD 回滚、`etl_run_log` 留痕（B-09 / C08）。

## E 诚实边界

数据由 `gen_data.py` 固定种子生成（2 万用户 / 8 万订单 / 3% 脏单），不是真实客户数据；Spark 在 Windows 偶发 worker 回连失败，已用 pandas 显式降级并在报告标注真实引擎；Hadoop/Flink 只做原理对照，没有集群经验；deferred 项：`GET_LOCK` 返回 NULL 分支（Q-002）、pyspark/pytest 的 CVE 升级（Q-005/006）、DB 账号 `@'%'` 收紧（Q-008）；慢查询未达 3 倍是数据量不足，不是伪造达标。
