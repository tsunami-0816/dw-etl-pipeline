## 二、上线方案

> 本项目为单机批处理数仓，无 HTTP 服务、无前端；「上线」= 在目标机拉起 MySQL 容器并跑通单日链路。

### 2.1 部署步骤（PowerShell）

```powershell
Copy-Item .env.example .env          # 填入口令，禁止提交
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
docker compose up -d                 # 仅 127.0.0.1:53306 暴露
.\.venv\Scripts\python.exe 05_代码/backend/scripts/run_sql.py --init
.\.venv\Scripts\python.exe 05_代码/backend/scripts/gen_data.py --days 90 --seed 42 --dirty-rate 0.03 --mode full
.\.venv\Scripts\python.exe 05_代码/backend/scripts/run_daily.py --date 2026-11-28
```

验收判据：最后一条退出码 0，`reports/run_summary.json` 中 `exit_code=0` 且 `layers` 各层行数非 0。

### 2.2 环境变量清单（只列键，值见 `.env.example`）

`MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_CONNECT_TIMEOUT`、`MYSQL_READ_TIMEOUT`、`MYSQL_WRITE_TIMEOUT`、`MYSQL_ROOT_PASSWORD`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_READER_PASSWORD`、`MYSQL_SEED_USER`、`MYSQL_SEED_PASSWORD`、`APP_ENV`

### 2.3 数据库初始化脚本（按序执行）

`sql/init/01_databases.sql` → `02_biz.sql` → `03_dw_ods.sql` → `04_dw_dwd_dim.sql` → `05_dw_dws_ads.sql` → `06_meta.sql` → `07_procedures.sql` → `08_init_dim.sql`

### 2.4 回滚方案

1. **代码回滚**：`git checkout <上一交付 tag/commit>` 后重装依赖、重启容器。
2. **数据回滚**：数据卷保留 `dw-etl-pipeline_dw_mysql_data`；如需回到交付时点，`mysql dw < 10_交付/db_backup/dw_full_20261124.sql`（先停写入）。
3. **干净重建**：`run_sql.py --init` + `gen_data.py --days 90 --seed 42` 可复现同一份模拟数据（固定种子）。
4. **容器回滚**：`docker compose down`（不删卷）→ 修改 `docker-compose.yml` 镜像/参数 → `docker compose up -d`；禁止用 `down -v` 以免数据丢失。

### 2.5 交付后健康检查

- 容器：`docker compose ps` 期望 `healthy`，端口仅 `127.0.0.1:53306`
- 链路：`run_daily.py --date 2026-11-28` 期望退出 0；同日重跑期望 `status=skipped` 且行数不翻倍（2026-11-24 实测：ODS 2601 / DWD 884 / DWS 31 / ADS 55，GMV 397131.3200）
- 质量：`run_rules.py --date 2026-11-28` 期望 0（无 P0）
